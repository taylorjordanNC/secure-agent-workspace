Use one control node for cluster administration, image mirroring, OIDC login,
and VM access. A RHEL 10 or Fedora bastion is the recommended path. A macOS
control node is suitable when Podman and the browser login have been validated.
Native Windows is not supported for this workflow; use a validated WSL2
environment or connect to the bastion.

Install these tools on the control node:

* `oc` and `kubectl` matching the OpenShift cluster
* Helm 3, Podman 4.3 or later, `virtctl`, Git, GNU Make, and `jq`
* `curl`, OpenSSL, Python 3 with PyYAML, SSH, and `lsof`
* OpenShell CLI container `{openshell_saw_version}` (all modules)

Obtain `oc` and `virtctl` from the OpenShift console client downloads so their
versions match the cluster. On macOS, start the Podman machine before deploying:

[source,bash,role="execute"]
----
podman machine init 2>/dev/null || true
podman machine start
----

Install the OpenShell CLI from its verified container image. The image
ENTRYPOINT is the CLI, its `HOME` is `/`, so the config mount target is
`/.config/openshell` (not `/root/.config`):

[source,bash,role="execute",subs="attributes+"]
----
podman run --rm --platform linux/amd64 \
  -v "$HOME/.config/openshell:/.config/openshell" \
  {openshell_cli_image} --version
----

To make `openshell` resolve to the container CLI in every module — including
the exercises' `make` targets, whose recipe shells are non-interactive
`/bin/sh` and do not expand aliases — write a PATH wrapper instead of a shell
alias:

[source,bash,role="execute",subs="attributes+"]
----
mkdir -p "$HOME/.local/bin"
cat > "$HOME/.local/bin/openshell" <<'EOF'
#!/bin/bash
exec podman run --rm --platform linux/amd64 \
  -v "$HOME/.config/openshell:/.config/openshell" \
  {openshell_cli_image} \
  "$@"
EOF
chmod 0755 "$HOME/.local/bin/openshell"
----

Ensure `~/.local/bin` is on `PATH` (add `export PATH="$HOME/.local/bin:$PATH"`
to your shell profile if it is not). A wrapper works in both interactive
shells and `make` recipe shells.

Verify every dependency before continuing:

[source,bash,role="execute",subs="attributes+"]
----
command -v oc kubectl helm podman virtctl git make jq curl openssl python3 ssh lsof
oc version --client
helm version --short
podman --version
virtctl version --client
openshell --version   # expect {openshell_saw_version}
----

Repeat the OpenShell version check in each new terminal used by the
exercises. The container CLI is `{openshell_saw_version}` for all modules, and
it matches the RHAIV gateway build it talks to — a client whose version does
not match the gateway build can silently stall during the login handshake.
